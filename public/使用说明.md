## 怎么用

上面填参数 → 下面出结果，按定价成本从低到高排。最便宜那行绿底加粗，
顶部也直接写着「最低定价成本 ¥xxx · 渠道名」。

**输入项**

| 项 | 说明 |
|---|---|
| 国家 | 列表 15 个：美、加、墨、澳、英、法、德、意、西、比、波、瑞、爱、沙特、阿联酋 |
| 重量 / 长宽高 | 用来算计费重 |
| 属性 | 普货 / 带电 —— 切换后只显示能接该属性的渠道 |
| 采购价 | 进货成本，算进定价成本 |
| 到账 | 卖到手的钱，算毛利 |
| 目标利润率 | 算建议售价 |
| 成本加成系数 | 默认 0.85（原表口径：售价 = 定价成本 ÷ (1−利润率) ÷ 0.85） |

表格里的「体积除数」列是每个渠道实际用的体积重除数，不同渠道不同，
这是最容易算错的地方，所以单独列出来。

**URL 参数预填**（方便存常用组合）：

```
index.html?country=德国&kg=8&L=45&W=35&H=25&attr=带电&buy=490&recv=1500
```

## 点选渠道

表格里**点任意一行**就能选中它：

- 选中行会高亮（蓝色左边条）
- 上方出现「已选渠道」面板，显示这个渠道的完整明细：
  定价成本、运费、挂号费、采购价、建议售价、当地售价、毛利额、利润比、
  计费重、体积除数、三档售价（30%/35%/40%）、时效、限制说明
- 面板还会算出**和最低价差多少**（贵多少 / 便宜多少 / 百分比）
- 点「复制这条报价」复制成文本，直接发给客户
- 点「取消选择」或再点一次那一行即可取消

最低价那一行始终是绿色的「最低」标记；选中别的行不会改变最低价。

## 计算口径（与《物流定价计算器》一致）

```
体积重 = 长 × 宽 × 高 ÷ 体积除数
计费重 = MAX(体积重, 实重)
运费   = 计费重 × 单价 + 挂号费  (+ 超尺寸加收)
定价成本 = 运费 + 挂号费 + 采购价
建议售价 = 定价成本 ÷ (1 − 目标利润率) ÷ 成本加成系数
当地售价 = 建议售价 ÷ 汇率（填了汇率才有）
毛利   = 到账 − 定价成本
```

三种计费方式：
- **按重分段** —— 运费 = ¥/kg 单价 × 计费重
- **首重续重** —— 首重价 + 续重单价 × 向上取整((计费重 − 首重kg) ÷ 续重步长)
- **体积除数** —— 三条产品线（重货实惠÷6000 / 泡货实惠÷10000 / 大泡货实惠÷18000）
  各按自己的除数算，**分行显示**，泡货走泡货线更便宜

## 体积除数从哪来

优先用《渠道整合报价》备注里的**逐国规定**（2026-10 最新）：

- 加拿大 8000、日本 9000、新加坡/马来西亚/泰国/越南 5000、
  新西兰/巴西/中东/阿塞拜齐等 6000、其余国家 8000
- 三态系列统一 6000（部分国家 12000）
- 专线按各自产品线除数

这些比《物流定价计算器》里的手工整理更新，所以以报价表为准。

## 尺寸限制

每行的「尺寸限制」列直接写出该渠道的实际规则，例如：

```
云途美国      最大 55×40×35cm · 加收后可发 68×43×43cm · 最小 10×15cm
4PX 加拿大    最长边≤100cm · 第二边≤76cm · 围长≤250cm
三态重货      最长边≤175cm · 长+2×(宽+高)≤340cm
欧盟P线       最长边≤175cm · 围长≤300cm · 实重≤30kg
```

判定逻辑（来自《渠道整合报价》的尺寸说明，比原计算器更新）：

| 限制类型 | 判定方式 |
|---|---|
| 最大三边 | 长宽高**降序**逐边比较（55×40×35 表示排序后 ≤ 55/40/35） |
| 两档尺寸 | 超标准档但未超前最大档 → 仍可发，**加收超尺寸费** |
| 最长边 / 第二边 | 降序第 1 / 第 2 边 |
| 围长 | 长 + 2×(宽+高)，取最长边作「长」 |
| 三边和 | 长 + 宽 + 高 |
| 实重 / 体积 | 实重上限、体积上限(m³) |
| 最小尺寸 | 任一边小于最小值 → 不可发 |

超过限制的渠道标橙色、不参与比价；全部超限时会提示「没有可发渠道」。

## 报价前仍要人工核对

这些**没有**计入金额：

1. 偏远地区附加费（英国、日本冲绳、法国海外省等）
2. 旺季附加费（有截止日期）
3. VAT / 关税
4. 申报价值限制与禁运品
5. 分区归属（澳大利亚 1–4 区、马来西亚东西马）—— 表里「分区」列标出
6. **汇率**：报价表与《物流定价计算器》全部以**人民币**计价，网站默认不换算。
   需要当地售价时，在「汇率」框填 **1 外币 = 几元**（如美元 6.69），表格会多出「当地售价」列。
   - 换国家时自动换成该国的参考汇率，汇率框下方会显示**取数日期**
   - 页面里的参考汇率来自 exchangerate-api.com 的实时数据，**2026-11-07 取数**
   - **报价前请按当天汇率改**（汇率框可以直接改，留空则不显示当地售价）
   - 刷新参考汇率：运行 `脚本/update_fx.py`

   > 注意：《物流定价计算器》里写的汇率（美元 6.91、欧元 7.98 等）已经过时，
   > 相对当前汇率普遍偏高 3–9%；沙特/阿联酋那两行的口径还是反的，不要照抄。
7. 「欧洲敏感专线-E」有**无服务邮编**限制（表里已列出，需人工核对）

## 验证

计算逻辑与《物流定价计算器.xlsx》逐格比对：

- 5 组不同参数（默认/小件/泡货/带电/轻小件）× 53 行 × 渠道 = 264 组
- 比对运费、定价成本、30%/35%/40% 三档售价、毛利
- **259 组完全一致，5 处不一致全部是原表自身的公式错误**

## 渠道有新价格了，怎么更新

### 最省事的做法：双击 `脚本\更新报价.bat`

1. 把新的《渠道整合报价》xlsx **放到 `脚本\` 文件夹里**（或放在桌面）
2. 双击 `脚本\更新报价.bat`
3. 跑完会打印**哪些价格变了**，并自动覆盖网站里的 `data_v2.js`
4. 打开 `index.html` 就是新价格

命令行用法：

```
cd 脚本
python 更新报价.py                       # 自动找最新的报价表
python 更新报价.py "D:\path\新报价.xlsx"   # 指定文件
python 更新报价.py --dry                 # 只跑流程, 不覆盖网站 (想先看变化)
```

### 输出的变化报告长这样

```
报价表: D:\Desktop\新报价表.xlsx

[3/4] 比对价格变化

【价格变动】1 条
  云途全球专线挂号（特惠普货） / 美国 / - / 普货 / - band 0.0-0.099kg
      运费 117.0 → 100.0   挂号费 24.0 → 24.0

【新增】3 条
【删除】0 条
```

每条变动都精确到「渠道 / 国家 / 分区 / 属性 / 产品线 / 计费方式 / 重量段」，
能直接核对你改的那一格。

### 只改了某个渠道的一两档价

一样用上面的流程 —— **报价表就是唯一数据源**，改表里的数字再重跑，
不要直接改 `data_v2.js`（那是打包产物，下次重跑会被覆盖）。

### 数据源在哪

| 文件 | 内容 |
|---|---|
| `脚本\源文件路径.txt` | 当前用的报价表路径（更新报价.py 自动写） |
| `脚本\原表路径.txt` | 《物流定价计算器》路径（抽尺寸/利润规则用） |

换新报价表时，只要把新文件放好，`更新报价.py` 会自动找到最新那份。
如果新表在别的盘，直接 `python 更新报价.py "路径"` 指定。

### 手工跑各步骤（调试用）

```
cd 脚本
python update_fx.py           # 刷新参考汇率 (实时)
python extract3.py            # 抽费率库
python extract_divider.py     # 抽专线
python extract_surcharges.py  # 抽尺寸限制 + 附加费规则
python extract_div_rules.py   # 抽逐国体积重除数
python extract_calc_rules.py  # 抽《物流定价计算器》的定价规则
python pack_data.py           # 打包成 data.json
python merge_data.py          # 合并 -> data_v2.js
```

`merge_data.py` 里有一道保险：只保留当前报价表 sheet 里存在的渠道，
换新报价表后旧渠道不会残留。

### 更新后建议核对

1. 看变化报告，确认改的价确实生效
2. 浏览器打开 `index.html`，用几个熟悉的重量档核对一下
3. 跑 `node verify_calc.js`（需要 Node），看计算逻辑有没有被影响
